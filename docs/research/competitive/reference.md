# Reference tier: browser hint extensions & keyboard-mouse tools — transferable interaction ideas

Ticket: #99 (child of map #94). Tier: **reference only**. These tools are mined for interaction ideas, not judged as competitors. Desk research only, from primary sources (READMEs, man pages, source, in-repo docstrings). Fetched 2026-10-13 from each project's default branch.

Tools covered: **Vimium**, **Vimium C**, **Surfingkeys**, **Tridactyl** (browser); **warpd**, **mouseless**, **keyd** (keyboard-mouse).

## Where Windows-Hinting stands today (for comparison)

- Labels come from `LabelGenerator.Generate` (`Windows-Hinting/Labels.cs`): spreadsheet-column style `A..Z, AA, AB, ...` over a fixed 26-letter alphabet, assigned in scan order. **They are not prefix-free.** `A` is a prefix of `AA`, so a commit key (`Space`/`Enter`) is needed every time.
- Selection works by typing the label only. You cannot filter by element name/text.
- One element per activation. Actions are UIA default plus Shift+key click variants (left/right/double/move/ctrl/shift). The named pipe accepts `label + action`.

## Transferable ideas

Each idea lists its source, how it could map to UIA, and the baseline item it overlaps (see "Baseline overlap note").

### A. Label generation

1. **Prefix-free ("short") labels, so no commit key is needed.** Vimium builds labels breadth-first over the hint alphabet and keeps only the leaves, so no label is a prefix of another. It needs at least 2 characters, because "with 1 character, every hint will be another hint's prefix" ([Vimium `link_hints.js` `hintStrings()`](https://github.com/philc/vimium/blob/master/content_scripts/link_hints.js)). Tridactyl `hintnames=short` (the default) "generate[s] short hints that are never prefixes of each other". `uniform` makes every label the same length, ⌈log_k n⌉ ([Tridactyl `excmds.ts` `:hint` docstring](https://github.com/tridactyl/tridactyl/blob/master/src/excmds.ts); [`hinting.ts` `hintnames_short`/`hintnames_uniform`](https://github.com/tridactyl/tridactyl/blob/master/src/content/hinting.ts)). **Transfer:** activation fires on the last label key, with no Space. Uniform length is a good fit for voice, because every utterance is the same shape. *Overlap:* #26 hint-engine phase.
2. **Home-row / configurable alphabets.** Each tool picks an ergonomic default: Vimium `linkHintCharacters: "sadfjklewcmpgh"` ([`lib/settings.js`](https://github.com/philc/vimium/blob/master/lib/settings.js)), Tridactyl `hintchars = "hjklasdfgyuiopqwertnmzxcvb"` ([`lib/config.ts`](https://github.com/tridactyl/tridactyl/blob/master/src/lib/config.ts)), Surfingkeys `asdfgqwertzxcvb`, and `Hints.setCharacters('yuiophjklnm')` for one-handed right-side use ([Surfingkeys README](https://github.com/brookhong/Surfingkeys/blob/master/README.md)). Vimium C has a `toggleLinkHintCharacters` command that switches between two alphabets ([Vimium C help_dialog.json](https://github.com/gdh1995/vimium-c/blob/master/i18n/en/help_dialog.json)). **Transfer:** make the alphabet a preference. A smaller alphabet also helps voice users, who can drop letters that are hard to tell apart in a spoken alphabet. *Overlap:* #26 preferences; Talon users already map the alphabet on the voice side.
3. **Spread labels evenly so neighbours don't share a first letter.** Vimium sorts the labels, then reverses them, so "hints starting with the same character and short hints are spread evenly" ([`hintStrings()`](https://github.com/philc/vimium/blob/master/content_scripts/link_hints.js)). Tridactyl `words` mode is "permuted and reversed" for the same reason ([`hinting.ts`](https://github.com/tridactyl/tridactyl/blob/master/src/content/hinting.ts)). **Transfer:** cheaper disambiguation, both visually and for speech recognition.
4. **Stable / predictable labels (numeric mode).** Tridactyl says this of `hintnames=numeric`: "a news site will have the same hints for its boilerplate each time you visit it, even if the number of links in the main body changes". The cost is that labels become prefixes of each other, so a commit key is needed ([`:hint` docstring](https://github.com/tridactyl/tridactyl/blob/master/src/excmds.ts)). Tridactyl also has `words` mode, which uses English words as labels. **Transfer:** for repeat Talon workflows, stable labels (for example keyed on UIA AutomationId/RuntimeId, or on scan order within a stable subtree) let users learn and memorise them. Word labels are a natural fit for voice. *Overlap:* not covered by any baseline item. Related to chained hinting #72, which uses RuntimeId reconcile.
5. **Reflow: give the survivors shorter labels after filtering.** Tridactyl `hintfiltermode=vimperator-reflow` calls `rename(active)` after each filter step ([`hinting.ts`](https://github.com/tridactyl/tridactyl/blob/master/src/content/hinting.ts)). Vimium renumbers filtered hints the same way ([`link_hints.js`](https://github.com/philc/vimium/blob/master/content_scripts/link_hints.js)). **Transfer:** pairs with text filtering (idea 7).
6. **"hintshift": predict the next hint during rapid mode.** If you skip over hints, Tridactyl shifts every label so that "once you pressed `c`, you can keep on pressing `c` to trigger every second hint" ([`config.ts` `hintshift`](https://github.com/tridactyl/tridactyl/blob/master/src/lib/config.ts)). Niche; worth noting only if multi-select (idea 11) lands.

### B. Text-filter / search hinting

7. **Filter by element text, not only by label.** In Vimium "filtered hints" mode, labels are digits and "you can also type the link text itself … when just one link is left, it is activated". There is always an *active hint*: `Tab` cycles it and `Enter` fires it. Matches are scored higher at text start, word start, and whole word ([Vimium C wiki "Using Link Hints"](https://github.com/gdh1995/vimium-c/wiki/Using-Link-Hints), forked from the Vimium wiki; [Vimium `link_hints.js`](https://github.com/philc/vimium/blob/master/content_scripts/link_hints.js)). Tridactyl `hintfiltermode=vimperator` interleaves label characters with text characters ([`hinting.ts`](https://github.com/tridactyl/tridactyl/blob/master/src/content/hinting.ts)). Surfingkeys `Hints.setNumeric()`: "Use digits as hint label, with it set you could type text to filter links" ([Surfingkeys API.md](https://github.com/brookhong/Surfingkeys/blob/master/docs/API.md)). **Transfer:** high value. UIA `Name` is the obvious text source. Benefits: you "know before hitting `f` what characters to type". For voice, "click Save" can resolve without reading labels. *Overlap:* none in the baseline. It is a selection-model change, so check it against #26 hint-engine intent/effect.
8. **Hint-by-text as a one-shot command (no overlay).** Tridactyl `hint -f Edit` and `-fr <regex>` hint only elements that display the given text. `-!` "execute[s] all hints without waiting for a selection", for example `hint -!bf Comments` ([`:hint` docstring](https://github.com/tridactyl/tridactyl/blob/master/src/excmds.ts)). Surfingkeys `Hints.click(selector, force)` clicks directly when only one element matches ([API.md](https://github.com/brookhong/Surfingkeys/blob/master/docs/API.md)). **Transfer:** a named-pipe or CLI verb like `click-by-name "Save"` (auto-fires on a unique match, falls back to showing filtered hints). This maps cleanly onto Talon. *Overlap:* integration surface (named pipe). Possibly #26 IPC.
9. **Auto-select on a single match, with an option to require Enter.** Tridactyl `hintautoselect` (default true). Vimium `waitForEnterForFilteredHints: true` exists because without it, typing past a hint causes "unintentionally executing Vimium commands" ([Vimium wiki tip](https://github.com/gdh1995/vimium-c/wiki/Using-Link-Hints); [`settings.js`](https://github.com/philc/vimium/blob/master/lib/settings.js)). Tridactyl `hintdelay=300` swallows extra keys after a selection ([`config.ts`](https://github.com/tridactyl/tridactyl/blob/master/src/lib/config.ts)). Surfingkeys `settings.hintExplicit` does the same job ([README settings table](https://github.com/brookhong/Surfingkeys/blob/master/README.md)). **Transfer:** a post-activation key-swallow window matters a lot OS-wide, because stray letters would otherwise type into the activated app.
10. **Spatial navigation of the active hint.** Tridactyl hint-mode commands include `focusNextHint`/`focusPreviousHint`/`focusTop/Bottom/Left/RightHint` + `selectFocusedHint` ([`hinting.ts` `getHintCommands`](https://github.com/tridactyl/tridactyl/blob/master/src/content/hinting.ts)). **Transfer:** "next/left/right" voice commands within a filtered set.

### C. Multi-select / continuous / repeat modes

11. **Stay in hint mode until Esc (rapid/queue mode).** Tridactyl `-q`: "Stay in hint mode until you press `<Esc>`" and return all results ([`:hint`](https://github.com/tridactyl/tridactyl/blob/master/src/excmds.ts)). Vimium `LinkHints.activateModeWithQueue` ("Open multiple links in a new tab") re-enters hint mode after each success, `activateMode(count - 1, …)`. A count prefix also repeats ordinary hints ([`all_commands.js`](https://github.com/philc/vimium/blob/master/background_scripts/all_commands.js), [`link_hints.js`](https://github.com/philc/vimium/blob/master/content_scripts/link_hints.js)). Surfingkeys `cf` "continuous following" and `Hints.create(…, {multipleHits: true})` ([README](https://github.com/brookhong/Surfingkeys/blob/master/README.md), [API.md](https://github.com/brookhong/Surfingkeys/blob/master/docs/API.md)). **Transfer:** ctrl-click several list items, tick many checkboxes. *Overlap:* **#72 chained hinting** (always-on-until-Esc), so fold in. Note the difference: browser queue mode keeps the *same* hint set, while #72 re-scans after each activation.
12. **Toggle modes with a held modifier while hints are up.** Vimium: holding Shift/Ctrl while typing a hint switches between current, background, and foreground tab ([`link_hints.js`](https://github.com/philc/vimium/blob/master/content_scripts/link_hints.js)). Vimium C: holding Alt toggles *queue* mode; Ctrl/Shift toggle new-tab/focus; `Ctrl+F2` toggles filter mode mid-session ([Vimium C `content/link_hints.ts` `toggleModesOnModifierKey`, `onKeydown`](https://github.com/gdh1995/vimium-c/blob/master/content/link_hints.ts)). **Transfer:** today's Shift+key click-type toggle is sticky. An optional *momentary* variant (hold Ctrl while typing the label means ctrl-click; hold Alt means stay in multi-select) saves keystrokes. *Overlap:* existing click-action toggles. A new variant, not a new capability.
13. **Re-hint without exiting, and auto re-hint when the target moved.** Vimium C: `Tab` (in non-filter mode) and arrow/page keys scroll the page *and* re-initialise hints. After a click, `checkLast` compares the clicked element's rect before and after, and re-hints if it vanished or moved more than 100px horizontally or 60px vertically ([`content/link_hints.ts`](https://github.com/gdh1995/vimium-c/blob/master/content/link_hints.ts)). **Transfer:** a "refresh" key, plus scroll-while-hinting followed by a re-scan. *Overlap:* #72 (settle/reconcile), #54/#62 (scroll).
14. **History hints: hint only recently used targets.** warpd History Mode is "identical to hint mode but exclusively displays hints over previously selected targets". `C-o`/`C-i` walk the history stack, and `--record` adds scripted clicks to history ([warpd man page](https://github.com/rvaiya/warpd/blob/master/warpd.1.md), [`src/config.c`](https://github.com/rvaiya/warpd/blob/master/src/config.c)). Vimium C `LinkHints.unhoverLast` ([help_dialog.json](https://github.com/gdh1995/vimium-c/blob/master/i18n/en/help_dialog.json)). **Transfer:** "repeat last activation" or "recent targets" per app (via UIA RuntimeId/AutomationId), which is cheap and needs no full scan. *Overlap:* none in the baseline. Gap candidate (taxonomy: repeat-last).

### D. Hint-action variety (UIA analogues)

15. **Action catalogue beyond click.** The browser tools offer these actions:
    - **Vimium:** open current/new-bg/new-fg tab, queue, copy URL, copy link text, hover, focus, download, incognito ([`link_hints.js` modes](https://github.com/philc/vimium/blob/master/content_scripts/link_hints.js), [`all_commands.js`](https://github.com/philc/vimium/blob/master/background_scripts/all_commands.js) `action: hover|focus|copy-text`).
    - **Vimium C** adds `activateEdit` ("Select an editable area"), `activateFocus`, `activateHover` / `activateLeave` / `unhoverLast`, `activateSelect` ("Select text and enter visual mode"), `activateCopyImage`, `activateSearchLinkText` ([help_dialog.json](https://github.com/gdh1995/vimium-c/blob/master/i18n/en/help_dialog.json)).
    - **Tridactyl** `:hint` flags: `-y` yank, `-p` copy element text, `-P` copy title/alt, `-h` select element text, `-r` **read text with TTS**, `-;` focus and make the element the scroll target, `-z` scroll it to the top, `-k`/`-K` delete/hide, `-s`/`-a` save, `-W excmd`/`-F callback`/`-pipe` pass the element to a command ([`:hint` docstring](https://github.com/tridactyl/tridactyl/blob/master/src/excmds.ts)).

    UIA analogues:

    | Browser action | UIA analogue |
    |---|---|
    | yank text | copy `Name` / `ValuePattern.Value` / `TextPattern` |
    | yank URL | `Value` of a hyperlink / `LegacyIAccessible.Value` |
    | focus | `SetFocus()` without invoking |
    | hover / unhover | mouse move (exists) + "move back" |
    | select text | `TextPattern` range select / `SelectionItem.Select` |
    | TTS read | send `Name`/`HelpText` to a screen reader or Talon |
    | scroll-target | `-;` matches the #62 pick-a-region model |
    | expand / toggle | ExpandCollapse / Toggle pattern as explicit actions |
    | pipe to command | return the element description over the named pipe to Talon |

    *Overlap:* #25 (multi-action buttons) and #8 (activator order) cover the *pattern choice* part. **Copy text, focus-only, select, read-aloud, and pipe-to-caller are not covered.**
16. **Element-scoped actions on a "region" pick.** Surfingkeys Regional Hints (`L`) picks "a visually large element", then offers `ct` copy text, `ch` copy HTML, `d` delete, `p` **select parent element** ([README](https://github.com/brookhong/Surfingkeys/blob/master/README.md)). **Transfer:** a "hint containers" mode, with walk-to-parent (UIA `TreeWalker` parent) and actions on that subtree (copy all text, scroll, scope next hint to it). *Overlap:* partly #62 scroll regions and #7 ("reduce search to active pane").
17. **Per-site/per-app selectors to add or remove hint targets.** Vimium C `clickable`/`match`/`exclude` CSS options, plus `clickableOnHost`/`excludeOnHost` keyed by host regex ([wiki "Add or remove hints"](https://github.com/gdh1995/vimium-c/wiki/Add-or-remove-hints)). Tridactyl `-c`/`-C`/`-x`/`-J` ([`:hint`](https://github.com/tridactyl/tridactyl/blob/master/src/excmds.ts)). Surfingkeys `settings.clickableSelector` ([README](https://github.com/brookhong/Surfingkeys/blob/master/README.md)). **Transfer:** per-app include/exclude rules on ControlType/AutomationId/ClassName. *Overlap:* #62 per-app profile (window rule grown) and #20 population strategies, so fold in.
18. **Overlapping hints: rotate or peek.** Vimium `Space` rotates the stacking order of overlapping markers. Vimium C adds `Shift+Space` to rotate in reverse. Surfingkeys holds `Shift` to flip, and holds `Space` to hide hints temporarily and see what is underneath ([Vimium C wiki](https://github.com/gdh1995/vimium-c/wiki/Using-Link-Hints), [`content/link_hints.ts`](https://github.com/gdh1995/vimium-c/blob/master/content/link_hints.ts), [Surfingkeys README](https://github.com/brookhong/Surfingkeys/blob/master/README.md)). Surfingkeys `hintAlign` = left/center/right. **Transfer:** directly answers #21's "handling overlapping hints". A "peek" hold key also helps sighted users check the target. *Overlap:* **#21**, so fold in.

### E. Fallback grids & pointer modes (non-UIA targets)

19. **Recursive grid fallback.** warpd grid mode "divides the screen into a 2x2 grid. Each time a key is pressed the grid shrinks to cover the targeted quadrant". `grid_nr`/`grid_nc` set the shape, `grid_keys "u i j k"`, `w/a/s/d` nudge the grid, `W/A/S/D` cut it ([man page](https://github.com/rvaiya/warpd/blob/master/warpd.1.md), [`config.c`](https://github.com/rvaiya/warpd/blob/master/src/config.c)). **Transfer:** a fallback when UIA exposes nothing (canvas, games, Monaco gutters). The Talon community mouse grid is the voice equivalent and sits in the primary tier (#95–#98).
20. **Two-stage hint mode (coarse label, then a fine sub-grid).** warpd `hint2`: a second hint grid of `hint2_grid_size` (3) around the first pick, with its own `hint2_chars` ([`config.c`](https://github.com/rvaiya/warpd/blob/master/src/config.c)). warpd also cautions against saturating the screen: "A balance must be struck between hint size, the number of hints, and the size of the screen" ([man page](https://github.com/rvaiya/warpd/blob/master/warpd.1.md)). **Transfer:** "hint, then refine" to reach a sub-point of a big UIA element (a pixel in a canvas, a text position), or blind screen-point hints when UIA is empty.
21. **Land in a pointer "normal mode" after a pick, plus oneshot.** warpd: after hint/grid you enter normal mode (`hjkl` nudge, `v` toggles drag, `e`/`r` scroll, `c` copy-and-exit). `--oneshot` exits after selection. `oneshot_buttons` click and exit. `--click <btn>`, `--drag`, and `-q/--query` take a hint list on stdin and print the chosen coordinates ([man page](https://github.com/rvaiya/warpd/blob/master/warpd.1.md)). mouseless: held keys move the pointer continuously, `speed <multiplier>` changes speed on the fly, and layers use `tap-hold` activation ([mouseless README](https://github.com/jbensmann/mouseless/blob/main/README.md)). **Transfer:** a post-hint fine-adjust/drag mode (hint the source, `v`, hint the target) gives **drag-and-drop between two hints**, which is not possible today. The `--query` idea suggests an external API: the caller supplies labelled points and gets back a pick. *Overlap:* none in the baseline for drag. Mouse Move (Shift+M) is a partial first step.
22. **Screen-selection hints.** warpd Screen Selection Mode gives "a dedicated set of hints for switching monitors" ([man page](https://github.com/rvaiya/warpd/blob/master/warpd.1.md)). **Transfer:** a multi-monitor scope picker. *Overlap:* taxonomy scope. Not in the baseline.
23. **keyd.** This is a key-remapping daemon (layers, `oneshot()`, `timeout()`). Its mouse support "is currently experimental", and the man page documents **no grid or hint mode** ([`docs/keyd.scdoc`](https://github.com/rvaiya/keyd/blob/master/docs/keyd.scdoc)). The only transferable idea is the oneshot/tap-hold activation model, the same one as mouseless. "keyd-style grids" in the map most likely means keynav-style bisection, which warpd grid mode covers (keynav is in the primary tier).
